# prd

PRD(Product Requirements Document, 요구사항 문서)는 **"무엇을, 누구를 위해, 어디까지"** 를 정한다. "어떻게, 왜 그 길을"은 ADR이 맡는다. 같은 질문에 두 문서가 답하면 반드시 어긋나므로, 서로 번호로만 가리킨다.

## 폴더

| 파일 | 답하는 질문 |
|---|---|
| `docs/prd/README.md` | 합의 상태, 제품 한 문단, 기능 목록, 범위 밖 목록 |
| `docs/prd/F-nn.md` | 기능 하나가 사용자에게 무엇을 해 주고, 무엇을 보면 됐다고 하나 |
| `docs/prd/questions.md` | 아직 정하지 않은 것은 무엇이고, 그동안 무엇을 가정하나 |

## 순서

1. `docs/GRILL.md`의 `결정`·`가정`과 과제 원문을 읽는다. **출처 없는 요구사항은 만들지 않는다.**
2. 기능을 사용자가 체감하는 단위로 나눈다. 과제 규모라면 보통 3~7개다. 과제의 **제출 조건**(실행 방법 README 등)도 기능 하나로 넣는다. 빠뜨리면 마지막에야 드러난다.
3. 기능마다 아래 틀로 `F-nn.md`를 쓴다.
4. `README.md`를 쓴다. **첫 줄은 `상태: 초안`이다.**
5. `열림`은 `questions.md`에 옮긴다.
6. 사람에게 기능 목록과 AC를 보여 주고 확인을 받는다. 확인을 받으면 첫 줄을 `상태: 합의됨`으로 바꾼다. **AI가 스스로 합의됨으로 바꾸지 않는다.**
7. 문체는 `docs/WRITING.md`를 따른다. 프로젝트에 그 파일이 없으면 이 스킬 폴더의 `references/WRITING.md`를 읽는다.

## 기능 파일 틀 — `docs/prd/F-01.md`

```markdown
---
id: "F-01"
title: "이메일로 가입한다"
priority: "필수"        # 필수 · 선택
status: "합의됨"        # 초안 · 합의됨 · 구현됨
source: ["과제 2절", "GRILL Q3"]
blocked_by: []          # questions.md 번호
---

# F-01 이메일로 가입한다

> 사용자 이야기: 재고 담당자는 이메일과 비밀번호로 가입해서, 자기 재고 목록을 따로 관리할 수 있다.

## 요구사항
누가 무엇을 하면 시스템이 무엇을 하는지 한 문단으로 쓴다. 처음 나오는 용어는 그 자리에서 푼다.

## 수용 기준
- **AC1** 올바른 이메일과 8자 이상 비밀번호로 가입하면 201과 사용자 id를 받는다.
- **AC2** 이미 가입한 이메일(대소문자 무시)로 가입하면 409를 받고, 사용자는 늘지 않는다.
- **AC3** 비밀번호가 7자 이하면 400과 이유 메시지를 받는다.

## 범위 밖
- 이메일 인증 메일 — 과제에 없음(GRILL Q4)
```

## 수용 기준(AC) 쓰는 법

- **입력 → 결과**가 드러나게 쓴다. 사람이 손으로 따라 해도, 테스트로 짜도 같은 판정이 나와야 한다.
- "빠르게", "적절히", "잘"을 쓰지 않는다. 숫자나 관찰할 수 있는 결과로 쓴다.
- 경계값(0, 빈 값, 최대치)과 실패 경우를 최소 하나 넣는다.
- 테스트에 `[F-01#AC2]` 태그를 붙인다. 이름에 괄호를 못 쓰는 언어(Python 함수 이름 등)는 docstring이나 테스트 설명 문자열에 넣는다. 구현 뒤 `grep -rn "F-01#AC" .`으로 AC마다 테스트가 있는지 확인하고, 빠진 AC를 보고한다.
- 구현 중 AC가 틀렸다고 판단되면 몰래 고치지 않는다. 차이와 이유, 번호 선택지를 사람에게 묻는다.
- **테스트를 AC보다 약하게 쓰지 않는다.** "항상 X"인 AC를 "일부를 빼고 X"로 검사하면 위반을 숨긴다. 기능을 끝내면 AC 문장을 하나씩 다시 읽고 실제 출력과 대조한다.

## questions 틀 — `docs/prd/questions.md`

결정이 나도 행을 지우지 않는다. 상태를 `결정됨(시각)`으로 바꾸고, 결론을 "지금 가정" 칸에 한 줄 적는다.

```markdown
| 번호 | 사안 | 지금 가정 | 영향 기능 | 상태 |
|---|---|---|---|---|
| Q1 | 결제 연동 방식 | 결제는 모의 응답으로 대신한다 | F-04 | 열림 |
```
