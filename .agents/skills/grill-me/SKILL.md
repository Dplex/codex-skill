# grill-me

목적은 정해야 할 것을 구현 전에 모두 끌어내는 것이다. AI가 빈칸을 추측으로 채우지 않는다.

## 1. 먼저 직접 확인한다

1. 과제 설명, 주어진 파일, 기존 `docs/`를 읽는다. 코드나 데이터로 답할 수 있는 것은 묻지 않고 직접 확인한다.
2. 데이터가 있으면 훑어서 **이상 신호**를 목록으로 만든다. 이상 신호 하나가 질문 하나다.
   - 시각에 시간대 표기가 없다 · 값의 범위가 업무 시간과 안 맞는다
   - 완전히 같은 줄이 있다 · 짝이 안 맞는 줄이 있다(시작 없이 끝만 있는 것 등)
   - README에 언급되지 않은 파일이나 열이 있다
   - 기준 시각·기준 대상이 정해져 있지 않다
3. 과제의 **제출 조건**(실행 방법 문서, 폴더 위치 등)을 따로 적어 둔다. prd 스킬에서 요구사항으로 옮긴다.

## 2. 질문은 누구에게 묻는지부터 가른다

| 대상 | 무엇을 | 형식 |
|---|---|---|
| **현업 담당자** (과제의 요청자, 채팅 상대) | 업무·판단 기준·데이터의 뜻·범위 | 업무 말로 쓴 **열린 질문** 한 문장. 선택지와 추천을 붙이지 않는다 |
| **사람(응시자)** | 기술 선택·구조·임계값처럼 담당자가 모르는 것 | 번호 선택지, 1번에 추천과 이유 한 줄 |

현업 담당자 질문은 사람이 채팅에 그대로 붙여 넣을 수 있게 따옴표 블록으로 준다.

```
[담당자에게] Q4
> 같은 알람이 여러 번 뜨는 건 평소에 어떻게 보세요?
(이유: ETCH-05 W-112가 24시간에 7번 찍혀 있습니다)
```

```
[직접 결정] Q9. 결과물 형태를 무엇으로 할까요?
1. 터미널에서 텍스트 출력 (추천: 결과를 카톡에 붙인다고 했습니다 — Q2)
2. 웹 화면
```

**현업 담당자 질문의 규칙**
- 한 번에 **질문 하나**. "A와 B는?"처럼 두 개를 묶지 않는다. 묶으면 앞의 것만 답이 온다.
- 개발 용어(dedup, API, DB, 컴포넌트)를 쓰지 않는다. "같은 줄이 두 번 있으면 어떻게 보세요?"처럼 쓴다.
- 선택지를 주지 않는다. 선택지에 AI의 추측이 섞이고, 담당자의 실제 답은 선택지 밖에 있을 때가 많다.
- 넓은 질문("요구사항 다 알려 주세요")을 하지 않는다. 장면 하나로 묻는다.

## 3. 묻는 순서

앞 답이 뒤 질문을 바꾸므로 사소한 것부터 깊게 묻는다.

1. **상황**: 누가, 언제, 어디서, 어떤 화면을 보며 하나. 결과는 어디로 가나. 근무·주기 같은 시간 단위
2. **지금 방식**: 지금은 어떤 순서로 하나
3. **불편**: 그중 무엇이 제일 오래 걸리고 무엇을 빠뜨리나
4. **판단 기준**: 무엇이 중요하고, 무엇을 먼저 보나. 오래된 것·반복되는 것은 어떻게 보나. 요청문에 나온 "~방식"은 무엇인가. 기준값과 정확히 같은 값(한계값 그대로, target과 같은 평균)은 어느 쪽으로 보나
5. **데이터 이상 신호**: 1단계 목록을 하나씩
6. **범위**: 꼭 필요한 것 → (다음 질문으로) 없어도 되는 것 → 데이터를 바꾸거나 써도 되나
7. **직접 결정**: 기술 선택. 담당자에게 묻지 않는다

## 4. 기록과 중간 확인

답을 받을 때마다 `docs/GRILL.md`에 한 줄씩 더한다.

```markdown
# 인터뷰 기록

| 번호 | 대상 | 질문 | 답 | 종류 |
|---|---|---|---|---|
| Q1 | 담당자 | 인계는 언제 어디서 하나 | 교대 직전 15분, 사무실 PC 한 대 | 결정 |
| Q5 | 담당자 | 같은 줄이 두 번 있으면 | MES 버그. 하나로 본다 | 결정 |
| Q8 | 응시자 | 결과물 형태 | 터미널 텍스트 | 결정 |
| Q9 | 응시자 | 페이지 크기 | 20건 | 가정(위임) |
| Q10 | 담당자 | 없어도 되는 것 | 아직 안 물음 | 열림 |
```

- 종류는 셋이다. `결정`(답을 받음), `가정`(사람이 위임해 AI가 추천안을 씀), `열림`(아직 답 없음).
- **답 3~4개마다** 들은 내용을 두세 문장으로 요약해 담당자 확인용 질문으로 만든다. 예: "> 정리하면, 인터락인데 안 풀린 게 제일 위고, 풀렸다 다시 뜨면 다시 안 풀린 거로 보면 되죠?"

## 5. 마무리

1. 3단계 순서에서 아직 안 물은 칸이 있으면 그 질문부터 낸다. 특히 "지금 방식", "불편", "없어도 되는 것"을 빠뜨리기 쉽다.
2. 사람이 "그만"이라고 하면 멈춘다. 결정·가정·열림을 각각 3줄 이내로 요약해 보여 주고 틀린 것이 있는지 묻는다.
3. 확인을 받으면 넘긴다.
   - 길이 둘 이상이었고 하나를 고른 결정 → **adr** 스킬
   - 요구사항·수용 기준·제출 조건 → **prd** 스킬
   - `열림` → `docs/prd/questions.md`
